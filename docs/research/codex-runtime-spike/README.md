# Локальная проверка Codex app-server

Одноразовый технический эксперимент, не код приложения. Проверяет реальное интервью и план, затем создание Markdown-файла в отдельной сессии и контейнере. Требует работающий Docker и локальный вход `codex login` через ChatGPT; расходует лимиты подписки.

Из корня репозитория:

```sh
docker build -t tutor-codex-spike:0.155.1 docs/research/codex-runtime-spike
python3 docs/research/codex-runtime-spike/run.py
```

В каждый контейнер попадает только временная копия auth.json и отдельный рабочий каталог. Исходные настройки, история Codex, файлы проекта и Docker socket не монтируются. Контейнеры останавливаются, а временные копии удаляются в конце штатного запуска или обработанной ошибки. При принудительном завершении процесса очистку нужно проверить отдельно. Контейнеры имеют сетевой доступ для обращения к модели; это не эксплуатационная конфигурация изоляции недоверенного кода.

Второй каталог содержит только approved-plan.json перед запуском генерации. Уникальная метка из первого диалога не передаётся и проверяется на отсутствие в результате. Это проверка конкретного пути передачи данных, не полное доказательство безопасности изоляции.

После успешного запуска result.json содержит идентификаторы разных сессий, выбранные модели и результаты проверок; sample-lesson.md — созданный материал. Файлы от прошлого успешного запуска не подтверждают новый запуск: проверяйте код завершения команды. Используются модели по умолчанию и короткие тестовые инструкции. Качество скиллов, экспертной основы, оценивания, выбор сильной/простой модели, Go, интерфейс и GitHub здесь не проверяются.

Тайм-аут ответа модели — 60 секунд. Первоначальный образ без системного пакета ca-certificates давал ошибку TLS UnknownIssuer; установка стандартного пакета устранила её, после чего получен реальный ответ модели. Проверка TLS остаётся включённой.
