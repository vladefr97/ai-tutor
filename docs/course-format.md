# Формат учебного курса

Согласовано 25 октября 2026 года. Документ описывает структуру содержимого; точная JSON-схема и имена файлов ещё не определены.

Курс содержит оглавление с модулями и входящими в них страницами. Каждая страница — упорядоченный список блоков. Блок может содержать текст в Markdown (включая пример кода) или учебный вопрос. Вопросы размещаются в нужных местах между объяснениями, отдельная вкладка тестов для них не нужна.

Пример последовательности блоков одной страницы:

1. Объяснение назначения `return` в Markdown.
2. Пример функции в Markdown с блоком кода.
3. Вопрос с вариантами ответа.
4. Продолжение объяснения в Markdown.

Для PoC согласованы три вида встроенных заданий:

- Выбор одного ответа из предложенных.
- Выбор нескольких ответов из предложенных.
- Короткий ответ свободным текстом.

Задания с кодом и проектные кейсы остаются отдельной практикой. Другие виды встроенных заданий в текущий объём PoC не входят.

Для выбора нескольких ответов зачёт требует выбрать все правильные варианты и ни одного лишнего. Порядок выбора не влияет на результат, частичных баллов нет. Неполный набор и набор с лишним вариантом не засчитываются. В учебном режиме первая ошибочная отправка даёт подсказку и возможность повторить попытку; вторая — разбор с правильным ответом. Подсказку и разбор Генератор создаёт вместе с вопросом и хранит в служебной части версии. Это правило действует только для встроенных вопросов; практика с кодом и кейсы автоматических подсказок не получают.

Короткий текстовый ответ проверяет Ревьюер работ соответствующего направления — та же роль, которая проверяет практику и pull request, а не Ревьюер плана. Проверка выполняется отдельным запросом с вопросом, критериями и конкретным ответом ученика; контекст других работ не примешивается. Оценка учитывает смысл и выполнение критериев, а не точное совпадение с образцом. Ревьюер возвращает зачёт либо необходимость исправлений с указанием, каких существенных частей не хватает. Для учебных попыток действуют общие правила помощи. Это решение о способе проверки, а не подтверждение качества оценивания моделью.

Генератор создаёт содержимое, последовательность блоков и деление на страницы. React-интерфейс отвечает за отображение этих блоков в согласованном дизайне. Материалы страницы не являются произвольным приложением, которое генератор должен самостоятельно верстать.

Генератор создаёт критерии зачёта одновременно с каждым заданием, опираясь на экспертную основу направления. Критерии описывают, какие существенные элементы должен содержать ответ или результат работы, чтобы задание было зачтено. Пользователь не составляет критерии каждого сгенерированного задания вручную. Ревьюер работ получает критерии соответствующего задания вместе с ответом ученика; верная формулировка своими словами допустима.

Перед публикацией курса Ревьюер работ соответствующего направления отдельно проверяет сгенерированные задания и критерии зачёта. Замечания возвращаются Генератору курса; он исправляет результат и передаёт обновлённую версию на повторную проверку. Курс становится доступным ученику после одобрения актуальной версии. Обязательное ручное участие пользователя не требуется. Это дополнительная обязанность существующей роли, а не новый агент. Проверка подготовки курса не смешивается с проверкой ответов учеников или ревью учебного плана. Наличие этого процесса не является доказательством безошибочности: методика измерения качества проверок остаётся открытой.

Правильные ответы и правила проверки хранятся отдельно от содержимого, доступного ученику. Они не отправляются браузеру вместе со страницей и не включаются в папку материалов Учебного наставника. Обратная связь выдаётся по правилам учебных попыток; самостоятельный итоговый экзамен остаётся отдельным сценарием.

Версия курса включает два варианта итогового экзамена на одни и те же навыки; они проходят то же ревью, что и остальные задания. Для Python и Git экзаменационные задания размещаются в учебном репозитории.

Версии курса сохраняются в S3-совместимом хранилище. Бэкенд сохраняет ссылку на используемую версию в БД и подготавливает из неё папку только для чтения для Учебного наставника. См. [ADR-0003](adr/0003-codex-runtime.md).

Остаётся определить: правила оценивания вопросов, точную схему блоков и ссылок, описание практических заданий, а также автоматическую валидацию результата генератора перед публикацией. Три страницы и три вопроса в макете — демонстрационные числа, не ограничения курса.

## Размещение материалов и практики

Теория и встроенные вопросы хранятся в S3 в составе версии курса и доступны ученику на сайте. Отдельный репозиторий теории не создаётся. В GitHub ученик получает репозиторий практики Python или Git с заданиями, заготовками и инструкцией запуска. В нём могут быть примеры локальных тестов. Официальные проверки хранятся отдельно под управлением платформы; изменение учеником файлов репозитория не подменяет их.
